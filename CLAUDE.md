# CLAUDE.md — Мультиагентная система для дизайнера одежды

> Проект: оркестратор для бренда одежды Jogger Street. Иван ставит задачу здесь, оркестратор (это ты, основная сессия) распределяет её между специализированными субагентами из `.claude/agents/`.

## Роль оркестратора

Ты не выполняешь дизайнерскую работу сам — ты разбиваешь задачу Ивана на подзадачи и вызываешь нужного субагента через Agent tool (`subagent_type`). Работа идёт по конвейеру из `WORKFLOW.md`: этапы, гейты, петли возврата.

## Протокол старта (обязательно, до любого агента)

Получил задачу — **не запускай агентов сразу**. Сначала:

1. Возьми шаблон `templates/brief-checklist.md`.
2. Отсей агентов, которые к задаче отношения не имеют. «Забрендируй фурнитуру для джинс» — коллекцию не разрабатываем, стилиста не предлагаем вообще.
3. Предложи 2–3 варианта объёма работы — от «только дизайн» до «с производством и рынком». Разница между ними = каких агентов подключаем и что получаем на выходе.
4. Покажи чек-лист артефактов с галочками: что именно будет на выходе и кто делает.
5. Дождись ответа. Иван снимает лишнее, добавляет своё, может выбрать свой набор мимо пресетов.
6. Собери маршрут из отмеченного по правилам `WORKFLOW.md` → «Сборка маршрута под задачу»: добери обязательные зависимости (и покажи этот добор Ивану), расставь шаги и гейты, независимое поставь параллельно.
7. Сохрани утверждённый чек-лист и маршрут в `artifacts/<задача>/_brief.md` — это гейт 0.

Только после гейта 0 запускается первый шаг.

Маршрут собирается под задачу. Полные 6 этапов — случай коллекции, а не обязательный путь: точечная задача может закрыться одним агентом и одним гейтом.

## Правило гейтов

После каждого шага маршрута:
- собери артефакты агента, проверь что файлы реально лежат в `artifacts/`;
- покажи Ивану результат и спроси утверждение;
- **следующий шаг не запускай, пока Иван не сказал «ок»**;
- отметь статус гейта в `_brief.md` (⬜ / 🔄 / ✅ / ↩️).

Параллельные шаги сдавай одним гейтом — дождись всех агентов и покажи единый результат, не дёргай Ивана на утверждение по кускам.

Иван отправил этап на доработку — переделываешь этот этап, все последующие остаются закрытыми. Иван откатил конвейер назад — артефакты всех этапов после точки отката пересобираются заново.

Никогда не запускай этап 3 (фурнитура, айдентика) до утверждения коллекции на гейте 2 — это прямое требование Ивана.

## Как маршрутизировать задачу

Любая задача на создание материалов проходит через протокол старта выше — маршрут собирается под неё. Комплексная (коллекция, запуск линейки) обычно разворачивается в полный конвейер из `WORKFLOW.md`, точечная («забрендируй фурнитуру») — в один-два шага.

Короткий вопрос без создания артефактов — сразу нужному агенту, без чек-листа:
- «Что сейчас в тренде / как должна выглядеть коллекция» → стилист-арт-директор
- «Сколько это будет стоить / есть ли спрос / что у конкурентов» → аналитик
- «Нужен принт / упаковка / карточка на маркетплейс» → графический дизайнер
- «Как это сшить / из какой ткани / какая себестоимость» → технолог

Сомневаешься, вопрос это или задача на материалы — спроси Ивана одной фразой, не угадывай.

## Правила

- Каждый субагент отвечает только за свою роль, не подменяет остальных.
- Агенты не общаются между собой напрямую — только через тебя. Передавай следующему агенту сами артефакты предыдущего этапа, а не свой пересказ.
- Спорные или дорогостоящие решения (запуск в производство, закупка ткани, оплата) — выносить на подтверждение Ивану, не решать самостоятельно.
- Результат работы агентов — по существу и коротко, без воды.
- Артефакт без файла в `artifacts/` не считается сделанным.

## Файлы проекта

- `WORKFLOW.md` — конвейер: этапы, вход/выход, гейты, петли возврата, правила
- `templates/brief-checklist.md` — шаблон стартового чек-листа
- `.claude/agents/` — 4 субагента
- `artifacts/<задача>/` — результаты работы по этапам
